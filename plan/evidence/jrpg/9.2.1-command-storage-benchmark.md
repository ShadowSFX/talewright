# Command storage benchmark (task 9.2.1, spec 03, D-058)

The gate of spec 03 before building the command model: 10 000 event commands (nested branches, about one command in
eight a branch with two child lists, down to depth 4) saved, loaded and saved again. Pass: load under 30 ms, save under
100 ms, the text file re-saved byte for byte.

Two storages of the same commands (`modules/jrpg/tests/test_jrpg_command_storage.h`):
- **typed**: one sub-resource per command (D-007 as first written), branches owning their child lists;
- **packed**: one resource holding the tree as nested arrays `[code, a, b, text, values, then, else]` (the spec's
  fallback), with the time to build the typed command objects again from it.

Text (`.tres`) is what the editor reads and what version control holds; exported games load binary (`.res`), since
exports convert text resources to binary by default (`editor/register_editor_types.cpp:310`, read at
`editor/export/editor_export_platform.cpp:1483`).

Run: `bin/godot.windows.template_release.x86_64.tests.console.exe --headless --test --test-case="*Command storage*" --no-skip`
(release template with tests, `python talewright/tools/build.py template-tests`; Windows 11, 32 cores, 2026-10-14).
Medians of three runs each; the editor build gave the same figures within a few percent.

| Storage | File | Bytes | Save | Load | Re-save identical |
|---|---|---:|---:|---:|---|
| typed | .tres | 1 826 242 | 69.2 ms | 102.4 ms | yes |
| typed | .res | 1 640 320 | 93.0 ms | 31.2 ms | no (binary is not kept under version control) |
| packed | .tres | 687 711 | 12.6 ms | 32.7 ms | yes |
| packed | .res | 743 992 | 8.1 ms | 12.8 ms | no |
| packed -> typed objects | | | | +5.2 ms | |

Result: typed resources miss the load gate (102 ms as text, 31 ms as binary, before any command runs). Packed
storage saves in 13 ms, re-saves byte for byte, and a game loads it and builds the command objects in about 18 ms.
D-007 is reversed as it planned: commands are stored packed behind `JRPGCommandList`, with the same typed command API
(D-058).
